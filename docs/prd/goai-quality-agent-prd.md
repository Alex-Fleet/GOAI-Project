# PRD：工业质量事故追责与全局处置 Agent

> 项目：GOAI 世界人工智能开源大赛 · 无界应用 · AI+工业制造
> 文档类型：产品需求文档（Product Requirements Document）
> 关联：docs/idea_v2.md（Idea v2 概念基线）

## 1. 问题陈述

制造企业发生质量事故（如某批次产品质检不合格）时，追责与处置依赖人工跨系统翻查：MES 查工艺、QMS 查检验记录、ERP 查工单与合同，影响面靠人脑估算。结果是**慢**（事故响应以天计）、**漏**（关联批次/客户易遗漏）、**不可审计**（结论无依据链，无法满足 IATF 16949 / ISO 9001 强制追溯与合规取证）。

质量追溯是工业强制要求，现有系统只能"事后查记录"，不能"主动推理、全链推演"。这是真实硬痛点，不是想象。

## 2. 目标与定位

一句话定位：**"AI 提出，逻辑审判"**——一个用领域本体做确定性推理、白箱可审计的工业质量事故追责 Agent。一次质检不合格，5 条推理链从缺陷追到设备根因、从根因前推到客户合同与产线重排，每个结论带依据链，决策正确性来自**本体逻辑证明**而非 LLM 概率。

- **做什么**：把"缺陷 → 工艺 → 设备 → 产品 → 客户 → 排产"的牵一发动全身，一次性推演清楚并可视化。
- **给谁**：质量工程师（追根因）、生产主管（处置排产）、合规审计（取证）。
- **解决什么**：追责慢、影响面算不清、结论不可审计。

> 定位取舍：作为 GOAI 演示作品交付，不期待真正被他人复用；但架构层面**本体域与数据沙盘解耦、配置驱动**，演示时展示"换行业仅换数据"的可复用能力，覆盖评审"开放复用价值"维度。

## 3. 目标用户 + 典型场景

| 用户 | 使用方式 | 频次 |
|------|---------|------|
| 质量工程师 | 事故发生时上传质检报告，看追责链与根因 | 偶发但高代价 |
| 生产主管 | 看影响面与处置方案，确认后执行 | 同上 |
| 合规审计 | 回放推理链取证、核对依据 | 审计周期 |

**典型场景走一遍**（演示主故事线）：

1. 质检发现"芯片批次 B-1024 引脚虚焊率 12%，超出 IPC-A-610 允收标准"。
2. **链1**：缺陷批次 → 工艺环节追溯（质量×工艺本体）：命中回流焊工序、温度窗口参数。
3. **链2**：设备根因诊断（设备本体 + 信号证据）：热风枪温控曲线漂移，判定为根因。
4. **链3**：影响面前推（BOM×工单本体）：B-1024 批次进入哪些在制品/成品、波及多少工单。
5. **链4**：客户合同影响（合同本体）：命中合同违约条款、召回范围与损失额。
6. **链5**：处置与产线重排（排产×供应链本体）：替代方案 + 产线重排建议。
7. 生产主管确认 → 系统更新沙盘、生成追责报告，全程每步白箱可回放。

## 4. 功能清单

**P0 · 核心闭环（一次事故 = 5 条推理链，全部必做）**

| # | 功能 | 对应痛点 |
|---|------|---------|
| F1 | 质检报告 NLU 解析（LLM 提取缺陷批次/缺陷类型/数值） | 人读报告慢、易错 |
| F2 | 链1：缺陷批次 → 工艺环节追溯（质量×工艺本体） | 追责查不到环节 |
| F3 | 链2：设备根因诊断（设备本体 + 信号证据） | 根因靠老师傅经验 |
| F4 | 链3：影响面前推 BOM×工单（波及在制品/成品/工单） | 影响面靠人脑估 |
| F5 | 链4：客户合同影响（召回范围/违约损失） | 损失算不清、无依据 |
| F6 | 链5：处置建议 + 产线重排替代方案（排产×供应链本体） | 处置靠经验拍板 |
| F7 | 三栏工作台 UI：推理链图谱 + 原始证据面板 + 影响处置看板 | 过程黑箱不可信 |
| F8 | 依据链：每个结论带原始证据 + 标准条款来源（白箱审计） | 无法合规审计 |

**P1 · 重要**

| # | 功能 | 对应痛点 |
|---|------|---------|
| F9 | 人确认 → 系统执行闭环（更新沙盘、生成处置单） | 说了不执行、无闭环 |
| F10 | Before/After 处置对比（处置前后影响面/损失变化） | 看不出 Agent 价值 |
| F11 | 合规映射展示（IPC-A-610 / ISO 9001 条款 ↔ 结论） | 标准强制、需取证 |

**P2 · 锦上添花**

- 追责报告导出（PDF）
- 本体一致性检测 / 动态分类演示（TBox 推理展示）
- 多起事故档案与历史比对
- 可复用展示：配置驱动切换行业/产品线（演示"换数据即换工厂"）

## 5. 不做清单

- ❌ 排产优化求解（OR-Tools/GA 求解器）——只给替代方案，不求解最优
- ❌ 收益最大化 / 定价财务模型
- ❌ 实时产线控制 / SCADA 接入
- ❌ 多 Agent 协作 / 多模型路由
- ❌ 完整 MES/ERP 复刻
- ❌ 真实合同的法律效力判断（只做条款命中与损失估算）

## 6. 成功指标（可验证）

- Demo 可在 **≤3 分钟**内走完一次事故完整闭环（7 步典型场景）。
- **5 条推理链全部点亮**，每条链 = 推理链高亮 + 原始证据 + 依据来源。
- 影响面数字（波及工单数 / 客户数 / 违约损失额）可对照沙盘数据**独立核验一致**。
- 有 **Before/After** 处置对比。
- 演示可见"换行业仅换数据"的可复用性（配置切换）。

## 7. 约束与风险

| 类型 | 内容 |
|------|------|
| 时间 | 初赛方案 2026-08-16 提交；复赛可运行 Demo 2026-09-03 提交 |
| 数据 | 仅开源数据 + 自建沙盘。信号层：NASA IMS / CWRU（设备退化）、SECOM（质检缺陷率背书）；知识层：IPC-A-610、ISO 9001 → 本体公理；业务层：自建 BOM/工单/客户/合同沙盘。所有来源须标注 |
| 技术 | owlready2/rdflib 本体推理；SQLite 沙盘；Streamlit 工作台；DeepSeek 仅做 NLU，决策不经 LLM |
| 行业 | 3C 精密电子（智能硬件 PCBA 组装），产品线：传感器模组/智能手表。故事链条、标准、数据源对齐此行业 |
| 架构约束 | 本体域与沙盘解耦、配置驱动，留可复用接口（定位取舍要求） |

**风险与待定**：

- **本体规模**：6 域（质量/工艺/设备/产品BOM/合同/排产供应链）建模工作量是最大风险，优先保证 P0 五链闭环，P2 展示性推理后置。
- **LLM 幻觉**：LLM 只产出结构化触发事件与人话解释，所有决策结论由本体逻辑产生，杜绝 LLM 直接出结论。
- **数据源细节**：NASA IMS/CWRU 与 3C 焊接场景的映射方式（信号形态背书）需在 demo 设计阶段定稿，待定。
- **指标口径**：演示时长与损失金额量级按上表执行，如需调整在 demo 验收时复核。

## 8. 验收标准

- [ ] 一次事故 7 步典型场景完整可演示，≤3 分钟。
- [ ] 5 条推理链全部点亮，每条结论可追溯到原始证据与标准条款。
- [ ] 影响面数字与沙盘数据核验一致。
- [ ] Before/After 对比可见。
- [ ] 可复用性（换行业/换数据）可现场演示。
