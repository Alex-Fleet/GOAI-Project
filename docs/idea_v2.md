# GOAI 参赛 Idea v2：工业质量事故追责与全局处置 Agent

## 一句话定位

**"AI 提出，逻辑审判"**——一个用领域本体做确定性推理、可解释、可审计的工业质量事故追责 Agent。

## 命题

一批产品质检不合格，牵一发动全身：缺陷 → 工艺 → 设备 → 产品 → 客户 → 排产。
Agent 用本体推理完成 **"向后追责 + 向前推影响"** 的完整闭环，每个结论带依据链、白箱可审计。

## 核心创新

- **业务创新**：质量追溯是工业强制要求（IATF 16949 等），AI 追责是真实硬痛点——从"被动质量报表"升级为"主动追责 + 全局处置"。
- **技术创新**：决策正确性来自**本体逻辑证明**而非 LLM 概率——LLM 只做理解与表达，**本体做裁判，人确认，系统执行**。
- **本体神力 n 次方**：一个大命题嵌套 5 条"牵一发动全身"的推理链，跨 6 个知识域，一次 demo 连续爆发多次推理。

## 五条推理链（一次事故 = 5 次本体推理）

1. 缺陷批次 → 追溯工艺环节（质量 × 工艺本体）
2. 设备 → 根因诊断（设备本体）
3. 根因 → 影响面前推（BOM × 工单本体）
4. 召回 → 客户与合同影响（合同本体）
5. 处置 → 产线重排与替代（排产 × 供应链本体）

## 三层数据

| 层 | 作用 | 来源 |
|---|---|---|
| 信号层（原始证据） | 质检失败记录、工艺参数、设备振动信号 | SECOM 半导体制造质量、NASA IMS / CWRU 轴承退化（真实开源） |
| 知识层（推理规则） | 焊接标准、质量追溯规范、故障模式 | IPC-A-610、ISO 9001 等公开标准 → 本体公理 |
| 业务层（叙事骨架） | BOM、工单、客户、合同、排产 | 自建模拟沙盘（行业标准做法） |

## Demo：事故追责工作台（三栏）

- **推理链图谱**（一步步点亮）+ **原始证据面板**（参数漂移曲线 / 振动频谱 / 条款原文）+ **影响与处置看板**（波及面、违约损失、建议方案）。
- 每一环 = 推理链高亮 + 原始证据 + 依据来源——白箱闭环，与"聊天机器人"的分界线。

## 技术栈

- 本体推理：owlready2 / rdflib（质量、工艺、设备、BOM、合同 5 域）
- 数据：SECOM + NASA/CWRU 预处理 + SQLite 沙盘
- 前端：Streamlit 追责工作台
- LLM：DeepSeek——仅做 NLU（解析质检报告）与人话生成，核心推理是本体引擎

## 概念定位

从"会调工具的聊天 Agent"到"**每个决策都过逻辑关的工业 Agent**"——正确性来自知识逻辑层，不来自模型概率。
