# GOAI 参赛 Idea v2：工业质量事故跨层溯源与责任定位 Agent

## 一句话定位

**"AI 提出，逻辑审判"**——一个用确定性推理做溯源、白箱可审计的工业质量事故 Agent。产品出问题，沿工艺链层层下钻，定位"问题怎么发生、责任在谁"。

## 命题

一批产品出问题 / 合格率下降，沿工艺链**分层溯源**：

```
产品 → 工艺图（n 设备 × n 外协件）→ 设备（判断点）→ 设备内部构造 → 部件/外购件 → 责任方（设备厂商 / 供应商）
```

每一层都是一张图，逐层钻取；每个结论带依据链、白箱可审计。

## 核心创新

- **业务创新**：质量追溯是工业强制要求（ISO 9001 / 行业标准），但现有系统只"查记录"不"推理"——从"被动质量报表 / 批次记录"升级为"**跨层溯源、定位责任机制**"。
- **技术创新**：决策正确性来自**确定性逻辑推理**而非 LLM 概率——LLM 只做理解与表达，**逻辑层做裁判，人确认，系统执行**。
- **跨层溯源推理**：产品问题沿工艺链逐层下钻（工艺图 → 设备 → 设备内部 → 部件），每层是图、每层带知识。追溯不是查表，是推理。
- **设备判断点**：定位到设备时做排除法——是设备自身故障（钻内部构造），还是它加工的物料/外协件故障（溯上游供应商）？两个方向都溯源。
- **责任归属终点**：溯源落到责任方（设备厂商 / 物料供应商 / 外协加工厂），直接对接索赔与追责。
- **证据不可篡改**：溯源全链哈希绑定，任一环节被改整链失效；可选上链存证，供供应商/客户侧独立验证，跨组织防抵赖。

## 分层溯源路径（一次事故 = 逐层下钻）

0. **触发**：产品质检不合格 / 合格率下降。
1. **工艺图层**：定位到这道工序 / 这台设备（n 设备 × n 外协件的复杂图，溯源到哪个环节）。
2. **设备判断点**：排除法——设备自身问题？还是它加工的物料（外协件）问题？
3. **设备内部层**：若设备问题，沿设备构造图定位到具体部件 / 外购件（轴承、电机、阀门…），机制明确。
4. **责任归属**：部件 / 外购件 → 供应商批次；设备 → 设备厂商。给出追责、索赔、处置建议。

## 三层数据

| 层 | 作用 | 来源 |
| --- | --- | --- |
| 信号层（原始证据） | 质检记录、工艺参数、设备振动信号——逐层定位的证据 | CiP-DMD 气动缸制造数据（工艺/质量/装配关系全真实）+ CWRU 轴承振动信号（设备部件层） |
| 知识层（推理规则） | 工艺图关系、设备构造手册、部件判定标准 | 机床/气动缸手册、ISO 9001 追溯条款、ISO 10816 振动分级、轴承特征频率 → 规则 |
| 业务层（叙事骨架） | 设备台账、外协件批次、供应商、工单、客户合同 | SQLite 模拟沙盘（同型号设备扩数量、供应商台账，行业标准做法） |

## 行业与数据（demo 定论）

**行业**：气动缸多工序机加工（离散制造）——直接采用 TU Darmstadt **CiP-DMD** 数据集的真实工厂场景，几乎不虚构。

**为什么选它**：产线级"工艺图规模 + 字段语义真实"的完整开源数据几乎不存在；CiP-DMD 是少数字段语义 100% 真实、且结构天然匹配分层溯源的多工序离散制造数据——工艺、质量、装配关系、外购件全都有名有义，不是匿名矩阵。规模偏小（真实设备 3 台、工序 4 道）的部分由业务沙盘扩同型号设备数量补足，真实信号仍挂在真实设备上。

**分层落点**（一次事故 = 逐层下钻，每层都有真实数据落点）：

| 溯源层 | 落点 |
| --- | --- |
| 产品层 | 气动缸成品（约 800+ 件，2,784 个零件）——CiP-DMD 真实 |
| 工艺图层 | 锯床 / 车床 / 铣床 3 台真实机床 + 装配站，4 道工序；沙盘扩到十几台同型号设备撑工艺图规模 |
| 设备判断点 | 设备自检：工艺参数（CiP-DMD ProcessRun 真实）——设备自身问题 还是 来料/外购件问题，两路都溯 |
| 设备内部层 | 机床主轴/进给轴承——CWRU 轴承真实振动信号（内圈/外圈故障可确定性定位） |
| 外购件层 | 壳体 / 活塞 / 密封圈 → 供应商批次（CiP-DMD 外购件 + 沙盘台账） |
| 责任归属 | 机床厂商 / 供应商（沙盘台账 + 合同条款） |

## 证据与防篡改（可审计底座）

- **哈希链（必做）**：输入数据 SHA-256 指纹；每一层溯源结论哈希与上层链接（H(输入) → H(层1) → H(层2) → …），任一环节改动即整链失效；生成"溯源根指纹"，可独立重算验证——把"白箱可审计"落到工程实现。
- **上链存证（加分项）**：溯源根指纹可打包上链，供应商/客户侧独立可查，作为跨组织责任追讨时"双方都认账、篡改即失效"的信任底座。demo 以哈希链模拟上链、答辩展示概念，不必真实部署区块链网络。

## Demo：溯源工作台（双栏 codex 式）

- **左栏 agent 聊天窗**（事故报告输入、推理过程流式输出、确认交互）+ **右栏内容区**（推理路径可视化逐层点亮下钻 + 仪表盘[事故进度/待处理项] + 原始证据面板[工艺曲线/振动频谱/参数漂移/手册条款] + 责任与处置看板[责任方、波及面、处置建议]）。
- 每一环 = 溯源链高亮 + 原始证据 + 依据来源——白箱闭环，与"聊天机器人"的分界线。

## 技术路线（阶段待定，不锁定选型）

- 推理：**神经-符号架构**——LLM / 多模态三职责：NLU 解析非结构化输入（质检报告 / 信号 / 图片）为结构化事实、**探索提议**（看图提议下钻方向与候选）、**人话表达**（把推理步骤说成人话）；确定性逻辑层负责溯源推理与决策把关，可审计可回放；具体形态（图遍历 / 规则引擎）按推理需求定。
- 数据：CiP-DMD 气动缸数据 + CWRU 轴承信号（真实证据层）+ SQLite 沙盘（设备台账 / 外协批次 / 供应商 / 工单 / 合同）。
- 前端：双栏溯源工作台（codex 式：左 agent 聊天窗 + 右内容区）。
- LLM：NLU 解析 + 探索提议 + 人话表达；提议未经推理核验证不得进入结论，不直接输出任何决策结论。

## 概念定位

从"会调工具的聊天 Agent"到"**每个决策都过逻辑关的工业 Agent**"——正确性来自知识逻辑层，不来自模型概率。
