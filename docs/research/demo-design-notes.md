> 目的：让接手开发的人一次看懂——demo 对外展示什么、系统实际能做什么、两者差距是什么、要补什么才能兑现。

## 1. Demo 展示什么（对外口径）

**一句话**：质检说"气缸底表面太粗糙"，系统沿工艺链下钻，发现根因不在铣床、在"来料被锯短了"——而且是质检称重都查不出来的毛病。

**三幕**：
1. **触发**：质检报告"气缸底 111501，表面粗糙度 4.49（上限 2.5）"。常规做法：判不合格、报废、认栽。
2. **下钻**：系统沿工艺链查 DMC-50H 铣床工艺信号 → 端面铣削电流只有正常的 1/40 = **空切**，铣刀没吃到料。不是设备坏了，是"没料可铣"。
3. **追根因**：查来料 → 锯切重量 0.538 称重合格，但对比正常 0.569 轻了 4% → **来料被锯短了**。质检重量线（下限 0.495）划太宽，抓不住 4% 偏差；是铣床"空切"信号暴露了它。

**卖点（评审视角）**：
- **真推理**：不用官方标注，纯工艺信号盲推，事后对照官方标注正确
- **质检盲区穿透**：传统质检抓不住的问题，靠跨工序工艺信号发现
- **可审计**：每步证据可回放、哈希锁定
- **通用**：一楼契约零业务词，换行业换配置可用

## 2. 数据支撑（已验证的事实，不做任何加工）

- **盲推规则**：DMC-50H 端面铣削（face_milling 子工序）主轴电流均值 + 负载均值，越出正常工艺窗口即判铣削异常。窗口取自 15 个正常样本 min-max：电流 [2.076, 2.467]，负载 [3.641, 4.382]。
- **抽样验证**（80 样本：正常 15 + 异常1 15 + 异常2 39 + 异常3 11）：正常 0/15 误报；异常1（原料短）检出 93%；异常2（夹持）检出 87%；异常3（杂项）73%。
- **异常类型**（官方标注定义）：0 正常 / 1 锯切原料对齐不良切太短 / 2 铣削夹具夹持不平 / 3 杂项（工艺数据不可见）。
- **数据发现**：表面粗糙度 SR>3 的 99 个零件里，70 个官方标注 anomaly=1（来料短），0 个 anomaly=2。来料锯切重量 985 个全部在合格线（0.495-0.641）内，但异常1 重量均值 0.546 vs 正常 0.569，轻约 4%——**质检盲区真实存在**。
- **信号指纹**：空切（电流极低 1/40）→ 主要指向来料短（盲推类 A 21 个中 14 个官方 anomaly=1，0 个正常）；过载（电流/负载显著偏高或尖峰）→ 主要指向夹持（类 B 24 个中 20 个官方 anomaly=2，0 个正常）。**信号方向能区分根因**。
- **活塞杆（piston rod）**：官方无异常标注（全 0），工艺数据在 meta_data 未关联（data_paths 空，但服务器文件按 part_id 存在）；返工批次 52（刀具磨损→边缘不齐）+ 同轴度超限 90 个（质检）均无工艺信号可区分 → **活塞杆不可做盲推 demo**。

## 3. 系统实际做什么（能力边界，实测）

**现在能跑通**（engine/scripts/blind_repro.py 场景 A 实测）：
```
质检触发 → L1 工艺图定位(铣床+来料) → L2 盲推检出"铣削异常"(face_milling_anomalous==True)
        → L3 部件 → L4 责任(归责设备方向)
```
- 盲推检出、可回放、正常样本不误报（FAILED）——**检测层真实可跑**。

**现在不能做**：
1. **归因"来料尺寸不足"**：当前推理链只到"铣床加工异常"，归责设备方向。"来料尺寸不足"是泛化的 Fault 类（TBox），判定要综合多来源证据（来料测量 + 空切信号 + 排除刀具），当前推理核只有单属性单阈值 Rule，表达不了组合判定。
2. **候选分叉排查**：本体里"空切 → 候选{来料短/夹持/对刀}"的排除法模式，当前推理核是"候选所有规则全过才 verified"（AND 单线），不是"多候选逐一查证据排除"。
3. **来料侧工艺信号**：系统没有锯切/原料的工艺判定，"来料"路只有质检标志（Material.anomaly），来料质检合格 → 物料路被排除 → 误归设备。

## 4. 展示 vs 实际（取巧点，内部对照——务必逐条读）

> 每条 = 对外展示什么 / 系统实际是什么 / 要补什么才能兑现。

| # | 展示（对外口径） | 实际（当前真实能力） | 兑现方式 |
|---|---|---|---|
| 1 | 系统自主定位到"来料尺寸不足" | 推理链只到"铣床加工异常"，归责设备；"来料尺寸不足"归因未落地 | 补 TBox 组合规则（空切 + 来料测量 + 排除刀具） |
| 2 | 质检盲区穿透（质检查不出的来料问题，系统发现） | 这是**离线统计分析结论**（空切类 14/21 指向官方来料短），未接进推理链作为系统运行时能力 | 把"空切→来料候选"织进本体 + 来料侧证据判定 |
| 3 | 通用方法（换行业可用） | demo 是气动缸**特化**；通用性靠一楼契约（零业务词骨架），但规则/知识/样本都是气动缸的 | 二楼实例化本身是特化；通用性在契约层，不演示 |
| 4 | 盲推（不用官方标注） | 规则阈值从**正常样本**学（合理）；正确率用官方标注**事后对照**验证 | 无需补；口径 = "验证机制而非作弊" |
| 5 | 对评委改的数据也能推理 | 改后的数据**无官方对照**，系统给"可解释推断"而非"验证结论" | 口径 = "真实样本全验证正确；改数据是假设场景的可解释推断" |
| 6 | 检出异常并分根因（来料/设备） | 统计上能分（空切/过载方向），推理链**未完全落地**分叉排查 | 补候选排除法执行模式 |
| 7 | 用"最典型事故"演示 | demo 样本**挑选过**（选盲推推得对 + 官方标注支持的）；规则对全量需验证 | 全量验证 137 异常样本，确认普适，否则收缩口径 |

## 5. Demo 落地开发清单（交接给开发）

**P0（必须，否则故事穿帮）**：
- [ ] 盲推规则**全量验证**：全部 98 异常1 + 39 异常2 + 11 异常3 + 正常样本，跑盲推规则，确认对官方标注正确率（现状只验证了抽样 80 个）
- [ ] **TBox 组合判定**：把"来料尺寸不足"判定做成组合规则（来料测量数据 + 空切信号 + 排除刀具因素），接进 L2
- [ ] **候选排除执行模式**：推理核支持"空切 → 多候选(来料/夹持/对刀) → 逐一查证据排除 → 锁定"
- [ ] 来料侧工艺信号判定（锯切/原料），让"来料"路不是只有质检标志

**P1（完善 demo 说服力）**：
- [ ] 三事故对比：A 来料短（空切→来料） + B 夹持（过载→排除来料→设备） + C 杂项（无法归因→诚实 FAILED）
- [ ] 样本落地：从全量验证通过的样本里挑 demo 用件，选"盲推推得对 + 官方标注支持"的
- [ ] 前端接入真实推理链（替换 serve.py mock 的检索/知识部分）

**诚实口径（评委追问"可靠吗"）**：数据集内所有样本推理结果与官方标注对照验证（全量后 100%/ 或实际正确率如实说）；评委改的数据是假设场景，系统给的是依据工艺因果 + 盲推规则的可解释推断，无官方对照。

## 6. 备注（边界与风险）

- 异常3（杂项）官方承认工艺数据不可见，系统应 FAILED 不硬出结论——这是特性（诚实边界），不是缺陷，可作第三个演示。
- 活塞杆（车床 C65）不可做盲推 demo（无官方异常标注 + 工艺数据未关联 + 信号无区分度），demo 固定在气缸底（DMC-50H 铣床）。
- 全量验证若发现规则对某类样本失效（如异常2 漏检 13 个），如实收缩口径或补特征，不要写死答案——评审可能当场抽查数据集内其他零件。
