# CiP-DMD 层2 盲推规则验证与数据发现

> 日期：2026-08-13 · 数据：CiP-DMD cylinder_bottom / cnc_milling_machine（Deckel Maho DMC-50H 铣床）
> 目的：验证层2 设备判断点能否仅凭工艺参数盲推异常（不用官方 `anomaly` 标注），并记录数据展示出的问题。

## 1. 数据与下载

- 数据源：TU Darmstadt ptW ownCloud 公开分享 `https://cloud.ptw-darmstadt.de/remote.php/dav/public-files/5Wv34VRZEXBLsZK/`
- 结构：`cylinder_bottom/cnc_milling_machine/process_data/<ProcessRun>/` 下每个运行含 frontside/backside 的 `internal_machine_signals.h5`（PLC 工艺参数，约 0.3MB）、`external_sensor_signals.h5`（外部加速度计，约 38MB）、`*_timestamp_process_pairs.csv`（子工序时间区间）
- `meta_data.json` 给出官方 `anomaly` 标注；`quality_data/quality_data.csv` 给出质检测量值（surface_roughness 等）
- 本验证只下载 frontside `internal_machine_signals.h5`（工艺参数是层2 盲推信号源），样本：正常 15 + 异常1 15 + 异常2 全部 39 + 异常3 全部 11 = 80

### anomaly 标注定义（README）

- **0** 正常
- **1** 锯切原料对齐不良（切太短）→ 原料异常 + 铣削过程异常
- **2** 铣削夹具夹持不平 → 铣削过程异常
- **3** 杂项错误（README 称工艺数据不可见）

## 2. 盲推规则验证结果

**规则**：取 `face_milling`（端面铣削）子工序的主轴 6 号通道电流均值 + 负载均值，越出正常工艺窗口即判该 ProcessRun 铣削过程异常。

- 正常窗口 = 15 个正常样本的 min-max：`aaCurr6_mean ∈ [2.076, 2.467]`，`aaLoad6_mean ∈ [3.641, 4.382]`
- 判定：`Curr6_mean` 或 `Load6_mean` 任一越出窗口 → 铣削异常

| 组 | 样本数 | 盲推检出 | 说明 |
|----|-------|---------|------|
| 正常 (0) | 15 | **0/15 误报 (0%)** | 窗口本身取自正常样本，无泄漏 |
| 异常1（原料短） | 15 | 14/15 (93%) | 端面铣削电流均值 0.02–0.64，**极低** |
| 异常2（夹持不平） | 39 | 34/39 (87%) | 电流/负载**偏离窗口**（偏高或偏低） |
| 异常3（杂项） | 11 | 8/11 (73%) | 部分样本工艺信号其实可见异常 |

**物理机制自洽**：
- 异常1 = 原料切太短 → 端面铣削近乎空切 → 主轴电流/负载极低（0.02–0.64 vs 正常 2.08–2.47）
- 异常2 = 夹持不平 → 工件位移/切削量变化 → 电流/负载偏高或偏低

**结论**：层2 设备判断点可仅凭工艺参数盲推异常，规则有效、误报为零，且与官方标注事后对照吻合（93%/87%）。demo 可声明"不用官方标注、纯工艺参数盲推"。

## 3. 数据发现：质检触发的主因与 PRD 预设冲突

对 `quality_data.csv` 与 `meta_data.json` 联合体检：

- **表面粗糙度（SR）超上限 2.5 的零件共 191 个；其中 SR>3 的 99 个零件里，官方标注分布：异常1（原料短）70 个、正常 0 个 27 个、异常3 2 个、异常2（设备夹持）0 个**
- 即：**SR 严重超标几乎全是来料（锯切原料太短）导致，不是 DMC-50H 设备自身（夹持）问题**
- 但来料质检（锯切重量）全部合格（0.495–0.641 区间内）——**质检盲区**：原料只是长度太短，重量不超界，靠称重查不出来；是铣削"空切"的工艺信号暴露了它

**与 PRD 预设的冲突**：PRD §1 层2 写"系统推理出 DMC-50H 铣床可疑 → 判设备自身问题；排除物料方向 → 锁定设备方向"。真实数据表明该场景下 SR 超标的主因恰恰是物料（来料）方向，且来料质检合格反而证明了"仅凭质检无法排除物料，必须依赖工艺信号"。

## 4. 对 demo 的启示

- 盲推规则验证成功（第 2 节），可作层2 判定规则；但 demo 追责主线应以数据为准：SR 超标事故 → 端面铣削空切（盲推检出）→ 指向来料尺寸缺陷（anomaly=1），而非 PRD 预设的设备自身
- 设备判断点的"排除法"需要补充"工艺信号归因"知识：空切（负载极低）→ 来料不足；过载/波动（负载偏离窗口）→ 设备自身（夹持/磨损）。当前一楼推理核无此归因规则——见复现验证
- 是否调整 PRD 层2 预设 / demo 主线的责任方归属，待用户拍板

## 5. 复现验证（本体推理能否复现上述发现）

`engine/scripts/blind_repro.py`：把真实样本的端面铣削工艺特征写入属性图（Equipment 节点 `face_milling_anomalous`），配盲推规则，跑一楼 `TracingLoop` 完整推理链。三个场景：

| 场景 | 输入 | 推理结果 | 结论 |
|------|------|---------|------|
| A：111501（来料缺陷） | 盲推检出（Curr6=0.07 空切），来料质检合格 | READY，追责 **SUP-A（设备方向）** | **复现"铣削异常→设备可疑"**，但**误归设备**：来料质检合格→物料路被排除 |
| B：100101（正常） | 盲推不检出 | FAILED（L2 无候选通过） | **不误报** ✓ |
| C：111501 + 来料工艺信号检出 | 盲推检出 + RM1.anomaly=true | READY，双路追责 **SUP-A + SUP-B（来料）** | **复现"根因在来料"需来料侧信号**，仅靠质检不够 |

**复现结论**：
1. 本体推理能**复现**"端面铣削异常 → DMC-50H 可疑"（盲推规则 + 推理核链路完整、可审计、可回放），且正常样本不误报——盲推验证闭环。
2. 本体推理**复现不了**"根因在来料"：现有 L2 物料判定依赖质检标志（Material.anomaly），而来料质检恰好合格（质检盲区），系统把 111501 归责到设备方向。
3. **缺口定位**：L2 判断点缺"来料侧工艺信号"检测（锯切/原料工艺），或"空切信号→来料尺寸不足"的归因知识。这与 §3 数据发现一致——要来料根因被抓到，需要来料侧工艺信号，仅凭质检不足。
4. 场景 A 的 L3/L4（主轴部件 SUP-A）是沙盘业务层（PRD 设计：业务层沙盘构造）；L2 判定是真实数据驱动。

**对二楼实例化的要求**：设备判断点的"排除法"需两路都接工艺信号——设备路（铣削空切→负载窗口）+ 来料路（锯切/原料工艺窗口），才能真实复现"来料缺陷"根因，而非只归设备。
